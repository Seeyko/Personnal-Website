### Key fixes that closed the gaps
- **LCP 10.4s→2.0s**: the static hero now paints immediately (no JS loading gate
  for default); non-default themes reveal the instant their CSS applies.
- **retro90s 71→99**: PostHog de-featured + all decorative effects (incl. the
  perpetual cursor-trail rAF and the status bar) moved to requestIdleCallback.
- **Desktop CLS 0.19→~0**: gate hides chrome with `opacity` (not
  `visibility:hidden`, whose reveal was recorded as a shift) + `scrollbar-gutter:
  stable` + default.css applied render-blocking + French static i18n text +
  metric-matched DM Sans fallback.

### Notes
- A rare (~15%) first-load desktop CLS spike can still occur uncached; it is
  benign in the field (CrUX) where the font/layout are cached.
- **Measurement gotcha**: `npx lighthouse` leaves headless `chrome.exe` procs
  alive across runs (~23 seen), starving CPU and tanking later scores. Kill
  `chrome.exe` between runs for stable local numbers.

## Root causes
1. **LCP killer**: `body.loading` hides all content (`opacity:0`) until the JS chain (theme CSS+JS,
   content fetches) finishes → hero text paints at ~10s.
2. **Render-blocking head**: 5 local CSS + 3 Google-Fonts stylesheets (all 6 theme font families) +
   synchronous `analytics.js`.
3. **Images**: 8.5MB of PNG/JPG carousel images loaded during run; no WebP, no srcset, no width/height.
4. **JS**: ~15 non-deferred scripts; GSAP from CDN; unused/legacy/duplicated JS; PostHog blocking.
5. **SEO/Best practices**: no robots.txt / sitemap / canonical / OG / JSON-LD / favicon / manifest;
   prod nginx `try_files … /index.html` makes /robots.txt serve HTML.
